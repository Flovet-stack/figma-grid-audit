# Project review: 2026-11-11

Reviewed by the product team (Tech Lead, Project Manager, Product Designer, UX, UI, Frontend). Database, Backend, Copy and Gamification were not needed: this is a client-only dev tool with no data store.

Scope: every file in `src/`, `public/index.html`, `package.json`, `tsconfig.json`, `tsup.config.ts`, `SOP.md`, `README.md`.

## Verdict: rethink

The idea is sound and the "Core + thin wrappers + Shadow DOM" direction is the same one serious tools use. But most features in the code either don't work or don't match the README, and nothing checks the code (no git, no tests, no CI, and the typecheck fails). The cheapest clear path is to **keep the idea, strip the code back to the grid overlay, and rebuild on proper foundations**. See the Proposed decisions in [`docs/decisions/`](decisions/).

## Evidence

- `npx tsc --noEmit` fails: `TS5107 moduleResolution=node10 is deprecated` (tsconfig). Once that is silenced, `overlay.ts` defines `setGridVisibility` twice, which is a compile error. So `dist/` was not built from this source, or was built while errors were ignored.
- No git repository, no tests, no CI, no licence file (`package.json` says ISC, `author` is empty).

## Findings

### Critical

| # | Problem | Why it matters | Fix |
|---|---|---|---|
| C1 | Guides never appear. `Ruler` dispatches `create-guide` on its own element with no `bubbles`/`composed`, and `ShadowOverlay` listens on the shadow root. The event never reaches the listener. | A headline feature is dead code. | Strip it (0001). Rebuild later behind a spec with a test. |
| C2 | The inspector can't be turned on. The README says `Shift+M`, but there's no handler for it. The panel checkbox is the only switch. | The second headline feature can't be reached the way the docs say. | Strip it (0001). |
| C3 | The README says `Ctrl+G`, but the code uses `Shift+G`. Its handler also fires while you're typing a capital G in any input, and calls `preventDefault`, so typing a capital G in the host app is swallowed. | The tool breaks the app it's meant to inspect, which goes against the SOP's main rule. | Choose a chord that doesn't clash, and ignore key events coming from editable targets (0002). |
| C4 | The panel's defaults (12/24/80, red) override the user's breakpoint config as soon as an input changes, and resizing the window then snaps back to the breakpoint config. | The settings come from two places, and it's unclear which wins. | One state store with one source of truth (0002). |
| C5 | Wrappers check `process.env.NODE_ENV` in browser code. In plain Vite or ESM there is no `process`, so this throws a ReferenceError or depends on the bundler replacing it. The core has no guard at all. | "Zero production footprint" isn't actually true, and in some setups it crashes. | The library never reads env. The consumer gates it with a dynamic import that's only reached in dev (0004). |

### High

| # | Problem | Fix |
|---|---|---|
| H1 | The grid math only handles Figma's **Stretch** columns. Figma's layout grids also have Left/Center/Right alignment with a fixed column width and an offset, rows, and a baseline grid. "Figma parity" isn't possible with this model. | Model Figma's grid types exactly, as pure functions with unit tests (0002). |
| H2 | `window.innerWidth` includes the vertical scrollbar, but layout uses `document.documentElement.clientWidth`. The columns drift by about 15px on Windows. | Measure the real container (`clientWidth` or a target element) and test for it. |
| H3 | The grid only covers the viewport (`position: fixed; 100vh`), so a page-level grid can't be checked against a centred max-width container. | Support a target container and its own content box. |
| H4 | Listeners are never removed: `destroy()` removes the DOM node but leaves the `resize`, `keydown`, `mousemove` and `click` listeners attached. React StrictMode mounts twice, so you get two copies. The React wrapper also re-inits on every render when `options` is an inline object. | Clean up with `AbortController` and keep `init` idempotent, so it can only run once. |
| H5 | `config.color` is ignored. The CSS hardcodes red. | Use CSS custom properties inside the shadow root. |
| H6 | The Vue and Svelte wrappers do nothing beyond calling `init`, the Vue `app` argument is unused, and there's no teardown. They're also untested. | Drop them. Vanilla `init` works in any framework (0002). |
| H7 | `public/index.html` loads the Tailwind CDN, which goes against the SOP's "NO external CSS frameworks" rule. It's a marketing page, not a test page. | Replace it with a small Vite playground of real layouts (0003). |
| H8 | Tooling: `moduleResolution: node` is deprecated, `@typescript/typescript6` and `typescript@5` are both installed, there's no `exports` map, and no publint or attw checks. | 0003. |

### Medium

- `mode: 'closed'` on the shadow root blocks Playwright and tests from reaching in. React Scan and VisBug both use open roots. Use `open`.
- `innerHTML` templates are used everywhere, and there are many `any` types. Use typed DOM builders.
- Use `console.log` only in development code paths, and never in a library.
- There are `z-index` max values everywhere. Use one top-layer host (`popover` top layer or a single fixed host).
- The README's "Professional" or "Ultimate" wording goes beyond what has been built.

## What the best tools do (research)

| Reference | What they do | Adopt / adapt / reject | Why |
|---|---|---|---|
| VisBug (Google Chrome Labs) | Vanilla web components inside Shadow DOM, shared token stylesheet, lives on any third-party page | **Adopt** Shadow DOM and a single token sheet | This is exactly our isolation problem |
| React Scan | Toolbar is a wrapper div with a shadow root, explicit `remove()` teardown, highlights drawn on a canvas, installed as a dev dependency | **Adopt** explicit teardown and a dev-only install. **Adapt** canvas, which is worth it for many lines and later for guides | Shows that mature overlays treat teardown and staying out of the app as first-class concerns |
| Chrome/Firefox DevTools grid overlays, VisBug measuring | These already handle measuring, padding and distances | **Reject** rebuilding a generic inspector | Our edge is *Figma grid parity*, not measuring things DevTools already does |
| tsdown + publint + attw | The 2026 library-build standard, with package lint and type-resolution checks run in CI | **Adopt** | Catches the packaging mistakes this repo already has |

## Path forward

1. Approve or reject decisions 0001 to 0004.

3. Spec 01 adds the grid engine as pure functions with exact Figma parity and unit tests.
4. Spec 02 adds the overlay renderer and the toggle, tested in a browser on the playground.
5. Spec 03 publishes 0.1.0. Only after that do we reconsider guides and deviation highlighting, each with its own decision.
